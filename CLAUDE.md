# CLAUDE.md — Raycast plugins monorepo

Orientation notes for Claude sessions. See README.md for user-facing docs.

## What this is

A monorepo of self-contained Raycast extensions. Each folder under `extensions/` is a full, standalone Raycast extension (own `package.json`, `node_modules`, config). A top-level `Makefile` is the command surface.

## Architecture — non-obvious decisions

- **No workspaces, no root `package.json`.** Every extension is fully self-contained. Can be lifted out of `extensions/` and still work standalone — that's the invariant to preserve.
- **Dynamic discovery.** The Makefile finds extensions via `$(wildcard extensions/*/package.json)`. No Makefile edits when adding/removing extensions.
- **`$(foreach)` + `$(eval)` generate per-extension rules, NOT pattern rules.** GNU Make skips implicit-rule search for `.PHONY` targets, so a pattern like `build-%` + `.PHONY: build-hello-world` silently becomes a no-op. Explicit generated rules avoid this pitfall.
- **`node_modules/.installed` sentinel** gates `npm install` to only re-run when `package.json` changes.
- **No global `@raycast/cli`.** `ray` is a dev dep of each extension via `@raycast/api`, invoked through `npm run`.

## Commands

Run `make help` for the current target list. TL;DR:

- `make deps` / `make build` / `make lint` / `make clean` — aggregate across all extensions.
- `make <verb>-<name>` — operate on one extension (e.g. `make build-hello-world`).
- `make dev-<name>` — runs `ray develop`, which registers the extension with Raycast and hot-reloads.

## Adding a new extension

Raycast scaffolding is GUI-only (`npm init raycast-extension` does not exist):

1. Raycast → **Create Extension** → save anywhere.
2. Move the folder into `extensions/`.
3. `make dev-<new-name>`.

Or: copy `extensions/hello-world/` and edit `package.json`.

## Known gotchas

- **`@raycast/eslint-config` v2.1.1 exports a nested array.** `raycast.configs.recommended` is itself an array that isn't spread upstream; ESLint 9's flat config rejects it. Each extension's `eslint.config.js` must flatten:
  ```js
  module.exports = require("@raycast/eslint-config").flat();
  ```
- **`ray lint` validates `author` against `https://www.raycast.com/api/v1/users/<author>`.** Even `--relaxed` does not skip this check. Expect `make lint` to fail with 404 until `author` is a registered Raycast Store user. Build and dev are unaffected.
- **Node 22.14+** is required by recent `@raycast/api`.
- **`ray develop` is the install mechanism.** There is no `ray install` and no `raycast://` deep link for programmatic local import. The extension is available in Raycast while `make dev-<name>` is running.
- **`raycast-env.d.ts`** is auto-generated by `ray build` in each extension root — gitignored at both root and per-extension level.

## Conventions

- Extension folder names are kebab-case and match the `name` field in their `package.json`.
- Each extension keeps its own `.gitignore`, `README.md`, `CHANGELOG.md`, `tsconfig.json`, and `eslint.config.js` so it stays portable if extracted.
- Commits use conventional commits (`feat:`, `fix:`, `chore:`, `docs:`); scope with the extension name for extension-specific changes (e.g. `feat(hello-world): ...`).
